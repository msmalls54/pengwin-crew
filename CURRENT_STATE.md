## The most important observed failure

On September 26 in live Slack, the user asked Pengwin Events **“what events do we currently have live”**. Events replied that it did not have the list and implied it could pull Eventbrite pages. The user then asked **“on oct 2nd”** and Events treated that as a new event-planning question. This is a real behavior gap, not just awkward wording. The October 2 event was already recorded as published, but `crew.dialogue.answer` sends Events' free-form question to `VultrInference.role_reply` with an empty `facts` string. Only Treasurer gets DB-derived facts; the model has no Eventbrite lookup tool or prior-turn context in that path. The user should not have to restate information Pengwin already has.

Postgres currently persists `CrewRun`, `AgentJob`, `AuditEvent`, `ControlFlag`, payments, and receipts. That is **partial task persistence**, not persistent conversational memory. Slack listeners pass the current message and `thread_ts` to the router; they do not load previous messages for an agent. `/crew latest` can show a user's latest run, but it is not a memory system. The newer thread approval binds an action to one saved draft; it does not solve conversational follow-ups. Avoid claiming that the agents can autonomously do arbitrary work from chat.
